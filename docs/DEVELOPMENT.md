# Правила разработки Chimera

## Стек
- Python 3.11 (ровно, `>=3.11,<3.12` — совместимость с Manticore для будущего общего лаунчера).
- Flask 3, Jinja2, немного ванильного JS (без SPA и без сборщиков фронтенда). Для перетаскивания — SortableJS из `static/vendor/` (файл в репозитории, без CDN).
- SQLAlchemy 2.x (ORM, типизированные `Mapped[...]`), Alembic для миграций.
- PostgreSQL 16 на сервере; SQLite в локальном режиме Windows-клиента. Код не использует диалект-специфичные возможности без обёртки; CI гоняет тесты на обеих БД.
- openpyxl/pandas — импорт/экспорт таблиц; docxtpl + python-docx — документы; fpdf2 — нативные PDF; pypdf — защита PDF.
- pytest, Ruff, mypy (strict для `chimera/core` и `chimera/services`).

## Структура
Весь код — в пакете `chimera/`. В корне репозитория нет `app.py`, `config.py` и других модулей (при объединении с Manticore в один лаунчер имена не должны конфликтовать).

    chimera/
      core/        будущий общий код с Manticore: конфиг, БД-сессия, auth, роли, аудит, тема/токены UI, оболочка desktop, обновления
      models/      ORM-модели по доменам
      services/    бизнес-логика без Flask (чистые функции/классы, тестируются без HTTP)
      web/         Blueprints по доменам; роуты тонкие: валидация → сервис → шаблон
      templates/   Jinja-шаблоны страниц
      static/      css/js/images
      documents/   встроенные .docx-шаблоны и движок документов
      importers/   импорт таблиц и профили сопоставления колонок
    migrations/    Alembic
    desktop/       Windows-клиент
    deploy/        docker, nginx, systemd
    tests/

Файл длиннее ~600 строк — повод разделить. Роут длиннее ~40 строк — логику в сервис.

## Данные и безопасность
- Все данные — персональные (152-ФЗ). В репозитории, тестах и фикстурах только синтетические данные (генерировать, например, Faker с локалью ru_RU). Папка `_samples/` с образцами от пользователя — в `.gitignore`, её содержимое никогда не коммитится и не копируется в `tests/`.
- Мультиорганизационность: каждая запись предметных данных принадлежит организации (`organization_id`). Изоляция обеспечивается на уровне сервисного слоя централизованно (базовый запрос с фильтром по текущей организации), а не вручную в каждом роуте. Тест на утечку между организациями обязателен для каждого нового модуля.
- Права проверяются в сервисах, а не только в шаблонах. Куратор видит только свои текущие группы; доступ к прошлым группам — только на чтение и только к записям, которые он создавал.
- Каждое изменение данных пишется в журнал аудита: кто, в какой роли, в какой организации, что, было/стало (для зашифрованных полей — только факт изменения).
- CSRF на всех формах, безопасные cookie, ограничение попыток входа, CSP без inline-скриптов.
- Пользовательские Jinja-шаблоны (.docx) рендерятся только в `jinja2.sandbox.SandboxedEnvironment`.

## Терминология
Тип организации (`university` / `college`) задаёт подписи в интерфейсе и метки документов через единый словарь `chimera/core/terms.py`:
факультет/отделение, направление подготовки/специальность, экзаменационная сессия/промежуточная аттестация, студент/обучающийся (настраивается), декан/заведующий отделением, кафедра/цикловая комиссия. В шаблонах и коде не хардкодить эти слова.

## Язык
Интерфейс, документация и описания PR — на русском. Сообщения коммитов и идентификаторы в коде — на английском. Релизы (заметки к выпуску на GitHub и раздел `CHANGELOG.md`) — на русском.

## Коммиты и авторство
- Автор проекта — UnicornisIT.
- Conventional Commits на английском: `feat(dossier): add student dossier`, `fix(auth): reset throttle after login`.
- Релиз выпускается только по решению автора; заметки к выпуску пишутся на русском.

## Готовность этапа
- `ruff check .`, `mypy`, `pytest` зелёные на SQLite и на PostgreSQL.
- Новая функциональность покрыта тестами сервисного слоя и хотя бы одним интеграционным тестом роутов.
- Обновлены `CHANGELOG.md` и пользовательская документация в `docs/`.
- Ничего не оставлено заглушкой без пометки: незавершённое помечается фича-флагом «В разработке» (см. `chimera/core/features.py`) и бейджем в UI.
