## Как читать матрицу

Инвентаризация содержит **82 позиций**. Индекс в конце сопоставляет **88 правил HTTP** из семи групп `routes/` и отдельного Blueprint сверки контингента с позициями матрицы. Одинаковые обработчики с разными URL посчитаны по правилам. Служебные алиасы `url_for`, статические ресурсы и неявные методы Flask в число правил не входят. Для Windows, сборки, фоновых действий и скриптов проверены отдельные точки входа. Изучены обработчики `app.py`, шаблоны и JS/CSS, SQLite и прикладные сервисы, тестовые фикстуры и актуальные руководства. Пробелы зафиксированы по проверенным деревьям.

В колонке Manticore «Есть» означает прослеживаемую реализацию, «Частично» — реализованную часть с ограничением, «Отсутствует» — возможность не обнаружена в проверенных точках входа и моделях. Запуск штатных тестов и пользовательская приёмка имеют собственные результаты ниже. Статусы Chimera:

- `EXISTS` — код аналога присутствует. `PARTIAL` — покрыта часть целевого сценария.
- `TO_IMPLEMENT` — требуется реализация. `BLOCKED` — есть блокирующий дефект или зависимость.
- `DOMAIN_DECISION_PENDING` — требуется решение владельца сценария. `EXCLUDED` — исключение в текущем контракте с причиной в строке.
- `ADAPTED_TESTED` оставлен для последующих этапов после фактического переноса и приёмочных проверок.

Проверки в строках — будущие критерии. Для сценариев с данными использовать отдельные синтетические профили, две организации и минимум две роли. Предметные функции запускать на SQLite и PostgreSQL 16, серверные исключения — OIDC и LAN-портал. На этапе 54 сначала фиксировать владельца и сценарий, состав данных, юридические основания, модель интеграции, позитивные и отрицательные тесты. Ответственные ниже указаны по направлению. Назначение конкретных людей относится к приёмке владельцем.

Remove-Item Env:CHIMERA_TEST_DATABASE_URL -ErrorAction SilentlyContinue
