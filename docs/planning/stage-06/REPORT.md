## Контракт

| Настройка | Desktop Local | Server |
|---|---|---|
| База | Файловая SQLite, драйвер `pysqlite`. Пустой URL выбирает `chimera.db` в каталоге данных. | Явный URL PostgreSQL через psycopg. Проверяется major 16 при каждом новом физическом подключении. |
| Пути | Новый Windows-профиль в `%LOCALAPPDATA%/Chimera`. Linux из исходников по умолчанию использует `instance`. Явный путь имеет приоритет. | Отдельный явный каталог, в образе по умолчанию `/var/lib/chimera`. |
| Запуск | `python -m chimera run` жёстко задаёт `127.0.0.1`. Werkzeug debugger и reloader отключены. | `chimera.wsgi:app` за доверенным HTTPS-прокси. `APP_DEBUG` запрещён. |
| Сессии | Loopback HTTP, `HttpOnly`, `SameSite=Lax`, существующая CSRF-защита. | `Secure`, `HttpOnly`, `SameSite=Lax`, существующая CSRF-защита. HSTS включается явно. |
| Секреты | Перечитываются из настроек или файлов профиля. Для новой SQLite ключи создаются эксклюзивно. Существующая база требует ключ подписи и исходный ключ шифрования. | Нужны явные ключ подписи и Fernet. Поддерживается ротация списком через запятую. `migrate` и `bootstrap` требуют ключи до подключения. `status` допускает диагностику без веб-ключей. |

Windows-запуск из исходников запрашивает явный `CHIMERA_DATA_DIR`, если
обнаруживает прежние локальные файлы в `instance`. Это сохраняет прежнюю базу
и ключи и исключает автоматический выбор общего каталога checkout на Windows.
Пути каталогов разрешаются от корня проекта, относительный путь SQLite URL
разрешается от рабочего каталога процесса. Проверяется тип существующего файла
и доступность ближайшего существующего каталога. Ошибки фактической записи
обрабатываются на границе запуска. Переключение режимов не переносит данные.

## Изменения по файлам

- `chimera/core/config.py` проверяет входы из окружения и прямой `Settings`.
  URL нормализуется через SQLAlchemy, секреты исключены из представления
  настроек. Отклоняются временный каталог распаковки и каталоги сборки.
- `chimera/core/db.py` проверяет PG16 при подключении до запросов ORM.
  `chimera/core/migrations.py` и `migrations/env.py` используют проверенное
  соединение и отклоняют неразмеченную схему с таблицами. Неизвестная ревизия
  по-прежнему блокирует обновление или запуск.
- `chimera/__main__.py`, `chimera/web/__init__.py`, `chimera/wsgi.py`
  применяют контракт при запуске, статусе, миграциях и bootstrap.
  Статус и bootstrap на отсутствующем SQLite-файле его не создают.
- `scripts/dev_test_env.py` сохраняет стенды этапа 02. `tests/conftest.py`
  отклоняет любое значение `CHIMERA_TEST_DATABASE_URL`, включая пустое.
  PostgreSQL-тесты поднимают новый кластер на 55439; браузерный стенд
  остаётся на своём порте 55432. Перед использованием тестового соединения
  сверяются каталог кластера, база, роль, адрес и порт. Очистка таблиц
  применяется к синтетической базе проверенного стенда. Убраны очистка схемы
  по произвольному URL и устаревший `deploy/dev-init.sql`.
- `tests/test_config.py`, `tests/test_core_units.py`,
  `tests/test_platform.py`, `tests/test_dev_test_env.py`,
  `tests/browser/stage04_smoke.py` проверяют новый контракт и его точки входа.
- `.env.example`, оба README, `CONTRIBUTING.md`, инструкции установки и
  развёртывания и документ о стендах описывают новые требования.
  Compose требует явный URL и публикует HTTP-прокси на loopback по умолчанию.
  Docker entrypoint, unit-файл systemd и CI приведены к новому контракту.

  `migrate`, `bootstrap` и автономной онлайн-миграции Alembic. Получение

## Инструкция ручной приёмки

1. На Windows запустите Desktop Local из исходников с временным синтетическим
   каталогом и пустым `DATABASE_URL`. Откройте `http://127.0.0.1:5000/login`,
   смените пароль тестового администратора и перезапустите приложение.
   Проверьте сохранение файла и ключей. Повторите с `APP_HOST=0.0.0.0` и
   URL PostgreSQL. Оба запуска должны завершиться с ошибкой до открытия порта.
2. Для Server укажите отдельный тестовый PostgreSQL 16, каталог и синтетические
   ключи. Выполните `python -m chimera migrate`,
   `python -m chimera bootstrap --no-input` и `python -m chimera status`.
   Запустите WSGI за доверенным HTTPS-прокси, проверьте вход и атрибут Secure
   у cookie. Повторите статус с пустым URL и проверьте сообщение без реквизитов.
3. В браузерном HTTP-стенде проверьте формы, таблицы, смену темы и навигацию.
   Для приёмки Docker повторите команды из CI на синтетических томах.
   Фактический TLS проверяйте с клиентской стороны на выделенном стенде.

## Ограничения и откат

Защита сетевой привязки распространяется на штатный `run` и поставляемую
WSGI-точку. Сторонний WSGI-хост, который импортирует фабрику Flask напрямую и
сам выбирает адрес, находится за этой границей. `ProxyFix` доверяет одному
непосредственному прокси. Доверие требует недоступности backend посторонним
клиентам. Встроенный HTTP nginx используется для проверки доступности.
Ошибка загрузки WSGI завершает работу мастера Gunicorn.
[Обработка завершения воркеров в Gunicorn](https://github.com/benoitc/gunicorn/blob/master/gunicorn/arbiter.py).

Дефект упаковки 00-01 остаётся в [реестре](../MANTICORE_FEATURE_PARITY.md).
Проверки ведутся из checkout, где есть ревизия `0001`.
Проверка архива PostgreSQL использовала обычный URL с хостом и портом.
Передача параметров маршрутизации и TLS в `pg_dump` проверена тестом с
подменой процесса. Параметры без соответствия в окружении libpq приводят к
безопасному отказу.

Для отката остановите процессы, сохраните копии БД, каталогов и ключей, затем
верните код и конфигурацию к проверенной версии. Для существующей установки
явно сохраните прежние пути, URL, тома и ключи. Перед запуском
проверьте совместимость ревизии со старым кодом. Если схема обновлялась
отдельно, проверьте восстановление копии из резервной копии в отдельной базе.
Этот этап не добавляет миграций и не требует downgrade.
