# Этап 03. Дизайн-система Chimera

Основа — боковая панель, верхняя панель, карточки и начальная загрузка темы из Manticore. Сверены `static/css/tokens.css`, `static/css/modern.css`, `static/js/theme.js` и `templates/base.html` локальной копии на ревизии `0e9e5d7`. В Chimera используется логотип из комплекта v2 и индиго-акцент.

| Область | Спецификация |
|---|---|
| Типографика | Segoe UI Variable Text, Segoe UI, системный шрифт. Основной текст 14 px, вторичный 13 px, заголовки 17 и 26 px при стандартном масштабе. |
| Поверхности | Холст, обычная, приглушённая и приподнятая поверхности. Отдельные значения для наведения и выделения. Тёмная боковая панель в обеих темах. |
| Размеры | Шаг отступов 4 px, основные интервалы 8–32 px. Радиусы 6, 9 и 13 px. Минимальная высота кнопок и полей 38 px. Две степени тени. |
| Интерактивность | Основная, вторичная и опасная кнопки. Наведение меняет фон, нажатие смещает кнопку на 1 px, `focus-visible` рисует обводку 2 px, отключённое состояние приглушено. Системная настройка уменьшения движения отключает переходы. |
| Обратная связь | Ошибка, успех, предупреждение и информация имеют текст и собственные цвета. Сообщения остаются видимыми до следующей страницы. Ошибки размечены как `alert`, остальные уведомления как `status`. |
| Темы | Три режима. Переключатель в оболочке и на экране входа, прямой выбор в профиле. Значение `chimera-theme` хранится в браузере, применяется скриптом в `head` до стилей. CSS выбирает системную схему и при отключённом JavaScript. |
| Логотип | Вход и регистрация показывают PNG под фактическую тему. Боковая панель использует вариант для тёмного фона в обеих темах. Иконка вкладки берётся из многоразмерного ICO, PNG 512 × 512 дополняет его. Обе версии README используют те же PNG с учётом темы браузера. |
| Адаптация | При 1024 px уплотняется верхняя панель, при 900 px боковая панель выдвигается, при 768 px сокращаются отступы, при 480 px действия входа становятся вертикальными. Широкие таблицы прокручиваются в области с клавиатурным фокусом. |

В `tokens.css` определены значения. `modern.css` задаёт оболочку и общие стили для элементов ввода и кнопок. `chimera.css` задаёт карточки, панели, формы, таблицы и уведомления. `pages/login.css` задаёт композицию экранов авторизации.

## Ручная приёмка

1. Запустите отдельный DEV-стенд по [инструкции этапа 02](../STAGE_02_TEST_ENVS.md). На странице входа переключите тему, обновите страницу и проверьте сохранение оформления. В системной теме смените схему ОС при открытой странице. Сверьте варианты логотипа на входе и регистрации, читаемость логотипа на тёмной боковой панели и иконку вкладки.
2. Войдите синтетическим администратором. На свежем стенде смените начальный пароль. Откройте «Профиль» и выберите каждый вариант в поле «Тема интерфейса». Сверьте состояние верхней кнопки, затем обновите страницу.
3. Откройте главную, профиль, смену пароля, административный обзор, организации и подразделения, пользователей, заявки, аудит, резервные копии и «Работать как…». Проверьте обе темы на ширинах 375, 768, 1024 и 1440 px. Для широкой таблицы прокрутите её отдельно от страницы. Повторите основной сценарий при масштабе 200%.
4. На узком экране откройте боковую панель клавишей Enter, пройдите по ссылкам клавишей Tab и нажмите Escape. Фокус возвращается к кнопке открытия. Аналогично проверьте меню профиля. Пройдите клавиатурой по полям, кнопкам и таблице.
5. Отправьте вход с неверным паролем, затем войдите успешно. Примените фильтр пользователей и завершите сеанс через меню профиля. Сверьте сообщения ошибки и успеха в обеих темах. Убедитесь, что отмена подтверждения удаления оставляет синтетическую запись на месте.
6. Повторите приёмку в браузере на изолированном Server/PostgreSQL 16. Когда доступен тестовый Windows-клиент, проверьте те же страницы в WebView2 в режимах Local и Remote.

## Повтор автоматической проверки

Установите Playwright в тестовую виртуальную среду. Скрипт использует установленный Microsoft Edge и принимает только адрес loopback. Запускайте на свежем или выделенном стенде. Он отправляет тестовый вход с неверным паролем, при необходимости меняет начальный пароль администратора и создаёт синтетическую резервную копию. Также проверяет скачивание, отмену удаления и выход.

```powershell
$py = ".\.venv-stage02\Scripts\python.exe"
& $py -m pip install playwright
& $py tests/browser/stage03_smoke.py --port 5801 --password-file .chimera-test-envs/sqlite/fixture_password.key --screenshots docs/planning/stage-03/screenshots
```

Для Server используйте порт 5802 и пароль собственного тестового PostgreSQL-стенда. Порог проверяемых текстовых пар — 4,5:1. Для проверяемых границ полей и обводок фокуса — 3:1. [WCAG 2.2, контраст текста](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [WCAG 2.2, контраст элементов](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

Штатные проверки в PowerShell из корня проекта.

```powershell
Remove-Item Env:CHIMERA_TEST_DATABASE_URL -ErrorAction SilentlyContinue
& $py -B -m pytest -q
& $py -m ruff check .
& $py -m ruff format --check .
& $py -m mypy
& $py -m build
```

Для теста временного кластера PostgreSQL 16 добавьте его `bin` в `Path`, освободите порт 55432 и установите `CHIMERA_STAGE02_TEST_POSTGRES=1` перед запуском Pytest. Основные фикстуры Pytest используют временную SQLite, а отдельный тест этапа 02 проверяет подготовку, перезапуск и очистку временного кластера PostgreSQL.

## Файлы этапа

- `chimera/static/css/` — `tokens.css`, `modern.css`, `chimera.css`, `pages/login.css`. Удалён `legacy.css`. Из современных стилей удалены селекторы, для которых в Chimera нет компонентов.
- `chimera/static/js/` — `theme.js`, `chimera-ui.js`.
- `chimera/static/` — `favicon.ico`, `images/chimera-head.png`, `images/chimera-logo.png`, `images/chimera-logo-dark.png`. Временный `images/chimera-mark.svg` удалён.
- `chimera/templates/` — `base.html`, `_ui_macros.html`, `no_organization.html`.
- `chimera/templates/auth/` — `login.html`, `register.html`, `profile.html`, `change_password.html`.
- `chimera/templates/admin/` — `audit.html`, `backups.html`, `divisions.html`, `organizations.html`, `requests.html`, `user_edit.html`, `users.html`.
- `tests/browser/stage03_smoke.py` и `docs/planning/stage-03/` — браузерный сценарий, спецификация и восемь снимков.
- `README.md`, `README.en.md` и `CHANGELOG.md` — логотип в документации и запись об обновлении. Старые SVG из `docs/images/` удалены.

«Выйти» в меню и при обязательной смене пароля, «Вернуться» из режима работы под другой ролью, «Удалить» в подразделениях и резервных копиях и «Скачать» в резервных копиях используют общие варианты кнопки. Переходы к карточкам и формам оставлены ссылками.

Действия с подтверждением активируются после регистрации обработчика. Это закрывает обнаруженное на тестовом PostgreSQL-стенде окно между отрисовкой формы и загрузкой обработчика. При отключённом JavaScript удаления, отклонение заявки и назначение временного пароля недоступны.

## Откат

Сохраните рабочие изменения этапа отдельно и вернитесь к `main` на `f85dc50` либо восстановите только изменённые файлы этапа из этой ревизии и уберите новые артефакты этапа. Если этап будет оформлен коммитом, используйте `git revert` для этого коммита. Действий с БД и миграциями для отката интерфейса не требуется. Удалять тестовые каталоги или пользовательские данные для отката не нужно.
