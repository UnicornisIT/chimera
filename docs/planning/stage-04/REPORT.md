# Этап 04. Навигация и оболочка Chimera

Рабочая ветка `stage-04-navigation-shell`, база `639415f02c70d53c183f9824cb7671ee52ce6437`. Оболочка этапа 03 включает исправление P2 из `0f8687e5`, вошедшее в базу при объединении этапа. Исходный промпт этапа сверён по приложенному `04_shell.md`.

## Навигация и верхняя панель

- Постоянное меню содержит «Главную» и две раскрывающиеся группы. «Управление» объединяет работу в текущей организации, «Системные операции» содержит создание организаций и резервные копии. Группа появляется, если пользователю доступен хотя бы один её пункт.
- Текущая страница получает `aria-current="page"`. На связанных страницах, например при редактировании пользователя, подсвечивается родительский раздел с `aria-current="location"`. Группа текущего раздела раскрывается при загрузке.
- Верхняя панель показывает текущий раздел, организацию, переключение темы и меню учётной записи. При наличии нескольких организаций выбор отправляется с проверкой CSRF. Сервер проверяет доступ, меняет контекст и завершает действующий режим «Работать как». Меню учётной записи сохраняет профиль, смену пароля и выход через POST. Во время обязательной смены пароля доступны форма, выход и выбор темы.
- В постоянном меню остались реализованные страницы. Карточки будущих модулей можно увидеть на главной как неактивные. Общие страницы ошибок содержат понятные сообщения без внутренних имён разрешений и подробностей исключений.

## Мобильная панель и доступность

- На десктопе состояние панели хранится в `localStorage`. При ширине до 900 px меню открывается поверх страницы и закрывается кнопкой, щелчком по затемнённой области или клавишей Escape.
- Фокус переходит на логотип при открытии и возвращается к кнопке при закрытии. Tab и Shift+Tab циклически обходят видимые пункты панели. Когда меню открыто, фон, переключатель организации и меню учётной записи получают `inert`. Закрытая панель также получает `inert`. Смена ширины пересчитывает состояние и восстанавливает фокус при уходе с видимой панели.
- Ссылка «К основному содержимому» доступна первой с клавиатуры. Навигация и меню учётной записи имеют доступные названия. Для раскрывающихся элементов синхронизируется `aria-expanded`. Используются существующие `focus-visible` и `prefers-reduced-motion`.

## Отличия от Manticore

Изучены четыре файла оболочки Manticore по локальной копии `0e9e5d7e4e902d126e4794f8cf3228e777a3beb5`. Сохранены знакомые принципы фиксированной панели, групп и верхнего меню. В Chimera видимость зависит от разрешений текущего контекста, а место глобального поиска занимает переключатель организации. Логотип Chimera v2 и токены светлой, тёмной и системной тем используются из этапа 03.

## Матрица доступа

Администратор в столбце «Адм.» означает администратора организации. «Системный» означает системного администратора с выбранной организацией. Для обычных ролей действия с учётной записью относятся к собственному профилю.

| Раздел | Адм. | Руководитель | Куратор | Староста | Наблюдатель | Системный | Основание |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Главная | Да | Да | Да | Да | Да | Да | `DASHBOARD_VIEW` в меню, активная сессия организации на маршруте |
| Профиль, пароль, выход | Да | Да | Да | Да | Да | Да | Собственная учётная запись и активная сессия |
| Переключение организации | По списку | По списку | По списку | По списку | По списку | По списку | `resolve_access`, интерфейс при двух и более организациях |
| Управление, обзор | Да | Нет | Нет | Нет | Нет | Да | `USERS_MANAGE` |
| Организации и подразделения | Да | Нет | Нет | Нет | Нет | Да | `ORG_MANAGE`, действуют границы текущей организации |
| Пользователи | Да | Нет | Нет | Нет | Нет | Да | `USERS_MANAGE` |
| Заявки | Да | Нет | Нет | Нет | Нет | Да | `REQUESTS_APPROVE` |
| Журнал аудита | Да | Нет | Нет | Нет | Нет | Да | `AUDIT_VIEW` |
| Включить «Работать как» | Да | Нет | Нет | Нет | Нет | Да | `ROLE_ACT_AS` |
| Новая организация | Нет | Нет | Нет | Нет | Нет | Да | `ORGANIZATIONS_CREATE` |
| Резервные копии | Нет | Нет | Нет | Нет | Нет | Да | `BACKUPS_MANAGE` |

В режиме «Работать как» действуют столбцы выбранной роли. Системные операции недоступны до возврата к реальной роли. Для возврата предусмотрена кнопка на постоянно видимой плашке.

Администратор организации управляет ролью и доступом в своей организации. Общие ФИО, почта и пароль учётной записи с членством в другой организации, в том числе отключённым, защищены серверной проверкой. Такая же проверка защищает учётную запись системного администратора. Форма показывает доступные действия.

## Ручная приёмка

1. Подготовьте отдельные стенды по [инструкции этапа 02](../STAGE_02_TEST_ENVS.md). Используйте тестового системного администратора, затем подготовьте пять обычных учётных записей. Одной учётной записи выдайте роль администратора в первой организации и роль наблюдателя во второй.
2. В Edge проверьте состав меню по матрице и прямой переход на `/admin/users`, `/admin/organizations/new` и `/admin/backups`. При недостаточных полномочиях сервер отвечает 403. Смените организацию и проверьте её название, роль и состав меню.
3. На ширинах 375, 768, 1024 и 1440 px проверьте светлую и тёмную темы. Дополнительно выберите системную тему в профиле и измените тему ОС. Проверьте меню, логотип, заголовки, переключатель организации и отсутствие горизонтальной прокрутки страницы.
4. На мобильной ширине нажмите Tab и Enter для перехода к содержимому. Откройте панель, проверьте Tab и Shift+Tab при открытой и закрытой группе, закройте Escape и щелчком по фону. Убедитесь, что фокус вернулся к кнопке, затем измените ширину при открытой панели. На десктопе сверните панель и обновите страницу.
5. Откройте меню учётной записи, перейдите в профиль и к смене пароля. Проверьте закрытие по Escape и щелчку вне меню, затем выход. В режиме «Работать как» проверьте плашку, отказ на прямых URL и возврат роли кнопкой «Вернуться».
6. Повторите применимые проверки на Server с отдельным PostgreSQL 16. Для установленного Desktop Local и Remote повторите проверку оболочки в WebView2 после штатного подключения к синтетическому стенду.

## Реестр известных ограничений

| Ограничение | Меры в проверках этапа |
| --- | --- |
| Штатный Server допускает SQLite fallback | PostgreSQL проверяется через явный отдельный кластер версии 16. |
| Штатный Desktop Local допускает внешний bind через `APP_HOST` | Браузерный стенд слушает только `127.0.0.1`. |
| В wheel отсутствует миграция Alembic `0001` | Стенды запускаются из рабочей копии исходников. |
| `CHIMERA_TEST_DATABASE_URL` может направить pytest на чужую БД, таблицы в которой тесты очищают | Для SQLite переменная снята. Для PostgreSQL адрес берётся только из выделенного синтетического стенда после проверки версии и каталога кластера. |
