# Этап 05. Формы, таблицы, уведомления и доступность

Ветка: stage-05-forms-tables. База: 7c10e162d16874bc0f63913092d3ff3f8002f0b0. В работе использованы локальный пакет требований, визуальная спецификация этапа 03, отчёт этапа 04 и исходники Manticore: макросы, оболочка, административный экран, список студентов, токены, стили, диалоги и поиск.

## Компоненты и страницы

- Общие стили полей, состояние ошибки, связь поля с подсказками и ошибками через aria-describedby, сводка со ссылками на поля. Обновлены регистрация, смена пароля, создание и редактирование пользователей, реквизиты организаций, создание и редактирование подразделений.
- Вход, выход, переключение организации, работа от имени другой роли, заявки, пароли и резервные копии используют общую индикацию выполнения POST в существующей оболочке. Flash-сообщения остаются видимыми до навигации. Успех и информация используют role="status", предупреждения и ошибки — role="alert".
- Таблицы пользователей, аудита, заявок, организаций, резервных копий и профиля используют подписанные области, заголовки столбцов и горизонтальную прокрутку. В структуре подразделений сохранено дерево. Ссылки «Изменить» в списках пользователей, организаций и в дереве получили существующий стиль вторичной кнопки. Ссылки по именам по-прежнему открывают карточки.
- Поиск пользователей охватывает ФИО, логин и почту, учитывает роль и работает с кириллицей без учёта регистра. Пользователи и аудит выводят по 50 записей, переносят фильтры между страницами и позволяют сбросить их одним действием. Символы подстановки трактуются буквально. В аудите можно указать любой логин, подсказки ограничены 50 логинами из журнала текущей организации. Ранее сохранённые ссылки с номером пользователя продолжают работать.
- Из README и скрипта синхронизации метаданных удалена подпись генератора в маркере. Из миграции удалены служебные комментарии генератора. SQL и версия миграции прежние.

## Валидация и отправка

Сервисы возвращают ошибки, связанные с полями. Фокус переходит к сводке, откуда можно открыть соответствующее поле. Браузер проверяет обязательные поля и формат почты до отправки. Сервер повторно проверяет данные и права, выполняет откат при ошибке и рендерит отправленные несекретные значения. Поля паролей возвращаются пустыми.

Удаление копии или подразделения, отклонение заявки и установка временного пароля открывают один нативный модальный диалог с описанием последствия. Начальный фокус на «Отмена». Tab и Shift+Tab циклически перемещаются внутри диалога, Escape закрывает его и возвращает фокус. Нативная модальность делает фон недоступным. Опасные POST проверяют признак подтверждения вместе с действующими проверками CSRF и полномочий. При выключенном JavaScript опасные кнопки недоступны и показана подсказка. Остальные формы сохраняют нативную отправку с серверной валидацией.

После валидного submit тело формы считывается до блокировки кнопки, включая имеющийся CSRF-токен. Интерфейс показывает «Выполняется…». Отмена диалога и клиентская ошибка происходят до блокировки. При успешном POST перенаправление открывается отдельным GET, при ошибке валидации обновляется содержимое страницы. Серверный контракт обычной отправки сохранён.

При обнаруженной потере связи до отправки пользователь может дождаться восстановления и отправить форму. Если сеть оборвалась после начала POST, приложение не ответило за 30 секунд или вернуло неопределённый ответ, сообщение предлагает проверить страницу через GET. POST автоматически не отправляется повторно. При восстановлении страницы с незавершённым запросом кнопка остаётся заблокированной, доступна проверка результата через GET. Поломка начальной загрузки страницы или потеря связи после полученного перенаправления может отображаться штатной страницей браузера или прокси.

Проверка статуса заявки защищает от повторного решения уже рассмотренной заявки. Повторное удаление требует существующего объекта, а членство проверяется сервисом и ограничениями БД. Клиентская блокировка действует внутри загруженной страницы. Параллельные вкладки и независимые запросы могут создать несколько резервных копий. Общий слой идемпотентности для этого этапа не введён.

## Предпубликационное ревью

- P2 — восстановление страницы из кэша браузера снимало блокировку при неизвестном результате записи. Исправлено: состояние запроса проверяется до разблокировки, незавершённый запрос помечается как неопределённый.
- P3 — список исполнителей загружал всё членство организации, а некорректные значения фильтров могли доходить до драйвера БД. Исправлено: ограничены подсказки, параметры нормализуются, смещение вычисляется только после ограничения номера страницы.
- Опасные POST получили проверку признака подтверждения. Серверная проверка полномочий, CSRF и методов маршрутов сохранена. Клиентская блокировка действует в пределах страницы.
- Регрессии покрывают откат общих данных пользователя и его прав, отсечение неверных фильтров, удаление последней строки страницы, обязательность CSRF и признака подтверждения, сохранение имени и значения кнопки, двойной Enter, обновление и возврат страницы, а также восстановление страницы с незавершённым POST.

## Реестр и откат

Открытых замечаний P1 и P2 в проверенных сценариях этапа 05 нет. P3: при недоступности сервера во время первой загрузки возможна штатная страница браузера или прокси. Пределы проверки режимов и доступности указаны в таблице выше.

Открытые вопросы прежних этапов:

| Проблема | Ограничение проверки |
| --- | --- |
| Server допускает SQLite fallback | PostgreSQL проверяется на явном выделенном кластере |
| Desktop Local допускает внешний bind через APP_HOST | Стенды используют 127.0.0.1 |
| Wheel не содержит миграцию Alembic 0001 | Стенды запускаются из исходников |
| CHIMERA_TEST_DATABASE_URL может указать pytest на чужую БД | Для SQLite переменная удаляется. В PostgreSQL адрес берётся из нового проверенного кластера |

1. Сохранить текущие локальные изменения и копию новых файлов этапа.
2. Вернуть отслеживаемые файлы из списка к 7c10e162d16874bc0f63913092d3ff3f8002f0b0. Новые файлы этапа убрать после сохранения копии. Серверный контракт улучшенной отправки и обслуживающий его JavaScript откатываются вместе.
3. Перезапустить тестовое приложение. Обновить страницу, проверить вход, пользователей, аудит и действия с синтетической копией.

Схема БД совпадает с базовой ревизией, поэтому откат миграций не требуется.
